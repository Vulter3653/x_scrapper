# 라벨링 가이드 — Fortune Top 100 유머 인간 코딩

이 파일은 코더 배정 템플릿(`coder1_labeling_template.csv`, `coder2_labeling_template.csv`,
`coder3_labeling_template.csv`, `coder1_labeling_template_batch2.csv`,
`coder2_labeling_template_batch2.csv`, `coder3_labeling_template_batch2.csv`)을
사용하는 코더를 위한 코딩 지침입니다.

---

## 입력값 코드 체계 (숫자 입력)

### 유머_존재여부 (human_humor_presence)

| 입력값 | 의미 |
|---|---|
| `1` | 유머 — 게시글에 의도적 유머 표현이 있음 |
| `0` | 비유머 — 정보 전달, 홍보, 공지, 캠페인 안내 등 유머 표현이 없음 |
| `2` | 애매함 / 판단불가 — 유머 여부 판단이 어려움 |

### 유머_유형 (human_humor_type)

| 입력값 | 유머 유형 | 설명 |
|---|---|---|
| `1` | AGGRESSIVE | 특정 대상을 깎아내리거나, 조롱하거나, 공격적으로 놀리는 유머 |
| `2` | AFFILIATIVE | 따뜻함, 유대감, 공동체 의식을 형성하는 유머 |
| `3` | SELF-ENHANCING | 상황의 우스꽝스러움을 즐기는 유머; 브랜드 자신이 상황을 웃음으로 승화 |
| `4` | SELF-DEFEATING | 브랜드가 자기 자신을 희화화하는 자조적 유머 |

---

## 템플릿 사용 방법

1. 배정된 CSV 파일을 열어 주세요.
2. 각 행의 `본문` 열을 읽어 주세요.
3. 다음 두 열에만 숫자를 입력하세요.
   - `유머_존재여부` — 0 / 1 / 2 중 하나
   - `유머_유형` — 유머_존재여부가 1일 때만 1 / 2 / 3 / 4 중 하나
4. 나머지 열은 절대 수정하지 마세요.
5. 열을 추가, 삭제, 이름 변경하지 마세요.

---

## 유머_존재여부 입력 규칙

**판단 기준:**

> "이 게시글은 의도적으로 웃기려 하는가?"

- 예 → `1`
- 아니오 → `0`
- 판단 불가 → `2`

---

## 유머_유형 입력 규칙

**유머_존재여부 값에 따른 입력 원칙:**

```
유머_존재여부 = 1 (유머)
  → 유머_유형에 1 / 2 / 3 / 4 중 하나 입력

유머_존재여부 = 0 (비유머)
  → 유머_유형은 반드시 공란으로 둔다

유머_존재여부 = 2 (애매함)
  → 유머_유형은 반드시 공란으로 둔다
```

## 핵심 구분: 기업 자신감 표현 vs. 공격적 유머 (AGGRESSIVE = 1)

이것이 Fortune Top 100 코딩에서 가장 중요한 구분입니다.

**기업의 자신감 있는 언어는, 명확한 유머 단서와 특정 대상을 향한 조롱·비꼬기·로스트식 언어·놀림·비하가 동시에 있지 않는 한, `1 (AGGRESSIVE)`로 코딩해서는 안 됩니다.**

| 특징 | 기업 자신감 표현 | 공격적 유머 (1) |
|---|---|---|
| 어조 | 자신감 있고 단호함 | 농담·로스트·비꼬기 |
| 대상 | 없음 (자사 제품·서비스 언급) | 명확한 대상 (경쟁사, 기관 등) |
| 유머 단서 | 없음 | 명시적 농담 구조 또는 희극적 표현 |
| 예시 | "우리는 시장 1위입니다." | "미안, [경쟁사]야, 이번에도 우리가 이겼네 😏" |

**기본 규칙:** 명확한 농담이 없고 비웃음의 대상이 없다면 `1 (AGGRESSIVE)`가 아닌 `0 (비유머)`로 코딩하세요.

---

## 판단 불가 케이스

다음 상황에서는 `유머_존재여부 = 2`를 사용하세요.

- 문화적 맥락이 필요한 유머 의도
- 가볍게 장난스럽지만 브랜드 개성인지 유머인지 모호한 경우
- 전체 본문을 읽은 뒤에도 판단이 어려운 경우

불확실할 때는 억지로 라벨을 붙이지 마세요. 유머_존재여부 = 2이면 유머_유형은 공란으로 둡니다.

---

## 참고 열 (수정 금지)

다음 열은 참고용으로 미리 채워져 있습니다. 수정하지 마세요.

- `웬디스_유머_존재여부` / `웬디스_유머_유형` — Wendy's 분류기 출력값 (참고만)
- `풀체인_유머_존재여부` / `풀체인_유머_유형` — full-chain 분류기 출력값 (참고만)
- `분류기_불일치` — 두 분류기가 다른 결과를 낸 경우 1
- `불확실성_점수` — 분류기 불확실성 (높을수록 판단이 어려운 게시글)
- `배정_코더` — 내 코더 배정 식별자 (수정 금지)
- `검토_상태` — 검토 완료 전: `pending` 유지. 완료 후: `complete`로 변경
